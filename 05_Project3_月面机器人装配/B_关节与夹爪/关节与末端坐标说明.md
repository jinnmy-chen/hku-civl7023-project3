## 2. 六个关节分别做什么

| URDF名称 | PyBullet实际索引 | 通俗作用 | 模型角度范围 |
|---|---:|---|---|
| joint1 | 1 | 底座转向，改变整条机械臂朝向 | -150.000° ～ 150.000° |
| joint2 | 2 | 肩关节，抬起或放下上臂 | 0.000° ～ 179.909° |
| joint3 | 3 | 肘关节，改变伸展／折叠程度 | -169.997° ～ 0.000° |
| joint4 | 4 | 前臂滚转，调整后端机构的旋转姿态 | -99.981° ～ 99.981° |
| joint5 | 5 | 腕部俯仰，调整夹爪倾斜方向 | -69.901° ～ 69.901° |
| joint6 | 6 | 末端滚转，调整夹爪绕末端轴的朝向 | -120.000° ～ 120.000° |

以上作用名称是便于理解的概括。严格运动定义以URDF局部转轴为准：六个旋转关节的`axis`均为`0 0 1`，即绕**各自关节坐标系的正Z轴**按右手规则旋转。关节坐标系随上游运动，因此不能把这句话理解为六个关节都绕世界竖直方向旋转。

把右手拇指指向关节的正轴，四指弯曲方向就是角度增大的方向。每个关节的数值零位来自模型，不等于出厂回零位置。演示初始角为`[0, 0.8, -1.2, 0, 0.4, 0]`弧度，是本组选择的展示姿态。

全部关节角为零、基座与世界对齐时，模型轴向约为：joint1沿基座+Z；joint2、joint3、joint5沿基座+Y；joint4、joint6沿基座`[0.9962, 0, 0.0871]`。这仅说明零位，运行中的转轴要随前级关节更新；精确数值见验证JSON。

程序通过名称查询索引，不假定“第7个索引就是夹爪”：模型还有固定关节，`gripper_base`实际索引为7，手指关节实际索引为8和9。

## 3. 夹爪怎样开闭

| 关节 | 作用与范围 | 张开时的目标 |
|---|---|---|
| joint7，索引8 | 第一根手指移动，0 ～ +0.035 m | `+w/2` |
| joint8，索引9 | 第二根手指移动，−0.035 ～ 0 m | `−w/2` |

`w`是本程序定义的**名义两指关节原点间距**，范围0～0.070 m。接口为：

```python
robot.command_gripper(0.0)   # 名义闭合
robot.command_gripper(0.04)  # 名义张开40 mm
robot.command_gripper(0.07)  # 名义张开70 mm
```

本模型未声明两指的`mimic`联动；新程序负责同步发送正负相反的目标。相对`gripper_base`，joint7正向移动主要沿−Y，joint8负向移动主要沿+Y，两根手指因此向相反方向张开。

70 mm来自URDF的两根手指行程之和，不是经硬件标定的净夹持空间、可抓物体宽度或夹持能力承诺。接口形状、碰撞余量及实际接触点需在后续单件抓取时检查。空载开闭也不能证明已能稳定抓住构件。

## 4. 与A、C统一的坐标约定

| 坐标系 | 定义 |
|---|---|
| 世界World | 本演示基座固定在原点、姿态为单位旋转，世界+Z向上；长度用m，角度用rad，时间用s |
| 基座Base | URDF的`base_link`；本演示与世界坐标重合，后续移动基座时需保留世界到基座的变换 |
| 机械臂末端Flange | URDF的`link6`坐标系，属于机械臂末端安装参考 |
| 夹爪基座 | `gripper_base`；通过零平移、零旋转固定关节与`link6`连接，两者坐标重合，但不是夹持中心 |
| 名义工具中心TCP | 在`gripper_base`坐标下位置`[0, 0, 0.1358] m`、姿态与夹爪基座相同，对应两指关节原点的名义中点；不是厂家提供的已标定接触中心 |

TCP的Z轴沿夹爪基座+Z，Y方向是名义开合方向；X由右手坐标系确定。这个TCP是明确声明的工作约定，后续按构件接触面和抓取位置需要可增加抓取偏移，不能把它当成已经验证的抓取点。

齐次变换采用`T_world_from_link`：将link坐标下的点变换到世界坐标；TCP关系为：

```text
T_world_from_TCP = T_world_from_gripper_base × Translation(0, 0, 0.1358)
```

程序的`robot.link_frame(name)`和`robot.tcp_frame()`均返回上述4×4变换。URDF原点的RPY按`Rz(yaw) × Ry(pitch) × Rx(roll)`解释。使用四元数时顺序为`[x, y, z, w]`。

**坐标核对的关键：**PyBullet的`getLinkState`第0／1项表示惯性／质心参考，第4／5项才是URDF link坐标。新增接口使用第4／5项，避免将夹爪质心误当成末端坐标。

本次验证结束时（电机实际状态，名义开度40 mm），TCP在世界坐标中的位置约为`0.268180, -0.000001, 0.508963 m`；这是一次演示姿态的例子，不是固定装配目标，完整变换与对应关节角见JSON。

## 5. 实际验证结果

| 检查 | 结果 |
|---|---|
| 六个关节独立正／反向运动 | 12个电机目标检查通过；每次从展示姿态单独改变±0.15 rad，再返回；未遍历全部可达空间 |
| 电机角度目标残差 | 本次最大约2.21e-05 rad（0.0013°）；仅为理想模型数值结果 |
| 夹爪开闭 | 两轮`0→20→70→0 mm`，8个停靠点均通过；使用位置电机和仿真步进，没有把关节直接重置到目标来冒充运动 |
| 夹爪同步与名义开度 | 两指目标、实际值、对称性及指原点间距均检查；最大间距残差约8.87e-06 mm，不代表硬件精度 |
| 坐标交叉核对 | 25组关节值，与独立URDF递推坐标计算比较；另设置非零基座平移／旋转，检查世界与基座没有混用 |
| 坐标计算差异 | 最大位置差约5.8e-08 m；旋转矩阵Frobenius差约5.22e-07 |
| 输入限制 | 6类非有限数值、尺寸错误或越界目标均被拒绝 |

图形自动演示也已运行完成，日志中的70 mm实际指原点间距为70.000008 mm，闭合实际间距为0.000008 mm。GUI采用实时仿真并在实际达到目标后切换动作，避免窗口刷新速度改变演示效果。日志见同一结果目录。

本次电机测试为固定基座、月面重力配置`[0,0,−1.62] m/s²`、无构件载荷、未启用机器人自身碰撞检测。它验证关节和空载夹爪控制；未验证抓取、避碰、接触稳定性或关节力矩准确性。测试容差是本组程序检查条件，不是课程评分门槛。
