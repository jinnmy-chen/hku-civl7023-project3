# C装配释放修复与验证

日期：2026年11月2日。当前状态：最终版本单次从零16件装配与独立核对通过。

## 问题与修复依据

原统一入口从零运行，完成前7件，第8件释放时开口停在30.23mm；左指残余接触、辅助约束未解除，未达到35.5mm开口及连续0.25秒稳定清空的条件。失败记录保留在`../C_整合验收_2026-11-02/`。

仅把释放力从1N分阶段增加到3N，能够通过第8件，但仍在第9件卡住，故不能把加力作为完整修复。对应失败为本目录`修复后从头16件/`。第9件失败快照显示，持久接触报告夹指受3.44N阻挡，缓存法向为约[0.643,-0.766,0]；即时几何查询则得到同一左指已有0.2068mm间隙，法向约[-1,0,0]。见`缓存与即时几何对照.json`，查询没有执行物理步或修改位姿。

据此判断，细小复合凸构件的旧接触法向在开爪过程中没有及时淘汰，是卡滞的重要原因。Bullet源码显示，接触缓存会沿旧法向刷新，并按接触距离与切向位移淘汰；默认全局参数为0.02，默认碰撞分派还会按形状尺寸缩放。这里的`contactBreakingThreshold`参数不能直接解释成“允许穿透多少米”。参考：[接触缓存实现](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/NarrowPhaseCollision/btPersistentManifold.cpp)、[碰撞分派](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/CollisionDispatch/btCollisionDispatcher.cpp)、[形状相对阈值](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/CollisionShapes/btCollisionShape.cpp)。该判断来自本机快照对照，不代表所有网格接触问题都由同一原因造成。

## 当前代码改动

| 项目 | 当前处理 |
|---|---|
| 接触缓存 | 在创建接触流形前设置相对参数0.00001；恢复旧检查点不能用来证明新参数的从零行为 |
| 物理积分 | 外部物理步仍240Hz、控制60Hz；每个物理步4个内部子步，即内部积分960Hz |
| 闭爪 | 每指1N；仍要求双侧夹持槽接触后才建立辅助约束 |
| 松爪 | 每指先1N，3秒仍不满足条件时最多3N重试；仍失败则报错保留约束；低于URDF每指10N上限 |
| 解除辅助约束 | 实际开口>35.5mm、无有效接触、线速度<2mm/s、角速度<0.02rad/s，连续5个50ms样本通过后才解除 |
| 诊断 | 记录实际两指位置、速度、驱动力、接触法向／力、约束反馈；卡住时保存Bullet快照和即时几何距离 |

`run_preloaded_tray_assembly_fast.py`为当前入口，`gripper_release.py`负责有界开爪与条件检查。B控制／运动学代码、原始URDF和构件V2文件没有修改。构件没有瞬移、运行中生成或固定到目标处；支撑／碰撞容差保持原值。`交接资料/实际仿真参数.json`按收到版本保存，其中旧5N和无子步的设置不是本次修复后的设置；当前以运行`result.json`的参数和本说明为准。

仅缩短接触缓存的试验也保留：`修复后从头16件_v2/`在第1件释放落地时触发0.2mm碰撞门槛；`接触缓存阈值对照/`为检查点续跑诊断，完成第9、10件后在第11件闭爪触发0.5mm夹持接触门槛。没有放宽门槛来掩盖这些失败。

在保留1N闭爪及4子步、相对参数仍为0.001的`修复后从头16件_v3/`中，单次从零完成前15件，最后第16件释放仍失败。该次两指实际几何间隙分别约19.10µm及8.20µm，但缓存仍报残余接触。最终将缓存相对参数细化为0.00001，重新从零验证；未把15件成功当作16件通过。
